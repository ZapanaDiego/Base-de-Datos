\section{Introducción}
Las bases de datos han dejado de ser un simple repositorio de información para
convertirse en un activo estratégico que sostiene la operación, la
personalización y la toma de decisiones de las grandes organizaciones
digitales. Hoy en día, empresas de comercio electrónico, plataformas de
entretenimiento y entidades financieras dependen de arquitecturas de datos
cada vez más sofisticadas —relacionales, NoSQL, en memoria y distribuidas—
para poder atender a millones de usuarios de forma simultánea, con altos
niveles de disponibilidad, seguridad y rendimiento.

En el presente trabajo se analizan tres casos de estudio: Amazon, que utiliza
bases de datos distribuidas para generar recomendaciones de productos en
tiempo real; Netflix, que procesa volúmenes masivos de datos (Big Data) para
analizar los patrones de consumo de sus usuarios; y un banco digital, que
requiere una gestión de datos segura y en tiempo real para prevenir el fraude
y cumplir con la normativa financiera vigente.

El objetivo de este informe es identificar, para cada organización, la
arquitectura de datos empleada, los flujos de información, las herramientas y
tecnologías específicas, las métricas de rendimiento y escalabilidad, las
medidas de seguridad y cumplimiento, el impacto que estas soluciones tienen en
el negocio, y los principales retos y lecciones aprendidas. Finalmente, se
presenta un análisis comparativo entre los tres casos, con el fin de extraer
conclusiones generales sobre el papel estratégico de las bases de datos en la
industria digital actual.

\section{Caso 1: Amazon --- Bases de datos distribuidas para recomendaciones}

\subsection{Arquitectura de datos}
% Responsable: Diego Eduardo Zapana Choquehuayta
Amazon utiliza un \textit{data lake} centralizado en Amazon S3, administrado
con AWS Lake Formation, donde se almacenan los registros de usuarios, las
transacciones y los catálogos de productos. Las consultas analíticas se
realizan mediante Amazon Athena (SQL \textit{serverless} sobre S3), mientras
que el proceso de extracción, transformación y carga (ETL) se ejecuta con AWS
Glue utilizando PySpark. Los modelos de recomendación se entrenan en Amazon
SageMaker y se ejecutan tanto en modo por lotes (\textit{Batch Transform})
como en línea, según el caso de uso.

El resultado final de este proceso —las listas de recomendaciones— se publica
en Amazon DynamoDB, una base de datos NoSQL de tipo clave-valor/documento,
totalmente gestionada y sin necesidad de administrar servidores, que ofrece
transacciones ACID y consistencia de lectura fuerte de forma opcional.
DynamoDB escala horizontalmente mediante particionado automático basado en la
clave primaria, y admite tablas globales replicadas en varias regiones para
garantizar alta disponibilidad.

Para las señales que requieren respuesta casi instantánea, Amazon complementa
esta arquitectura con Amazon MemoryDB, una base de datos en memoria compatible
con Redis, organizada en particiones (\textit{shards}) con una réplica
primaria y hasta cinco réplicas de lectura por partición, lo que le permite
ofrecer latencias de lectura del orden de microsegundos.

\subsection{Flujos de datos y pipelines}
% Responsable: Diego Eduardo Zapana Choquehuayta
El flujo de generación de recomendaciones comienza en el \textit{data lake}
(Amazon S3) y es orquestado mediante Amazon MWAA (Apache Airflow gestionado).
En primer lugar, se extraen los datos históricos utilizando Athena y Glue; a
continuación, estos datos alimentan el entrenamiento del modelo en SageMaker.
En cada ciclo del proceso se aplica una inferencia por lotes (\textit{Batch
Transform}), que genera vectores de usuario y de producto.

Posteriormente, se realiza una búsqueda por similitud (\textit{Approximate
Nearest Neighbors}, ANN) empleando la librería FAISS dentro de SageMaker
Processing, y los resultados obtenidos se combinan y reordenan mediante un
proceso adicional en Glue. Finalmente, las recomendaciones calculadas por
lotes se almacenan en DynamoDB para su consulta desde las aplicaciones, y las
señales dinámicas (por ejemplo, vectores de productos vistos recientemente) se
envían a MemoryDB para su uso en consultas en línea de muy baja latencia.

Este diseño híbrido, que combina procesamiento por lotes (\textit{batch}) y en
tiempo real, permite que Amazon trate primero las señales más estables (como
el historial de compras o las relaciones entre productos del catálogo) de
forma económica y eficiente, para luego añadir filtros y reordenamientos en
tiempo real únicamente donde realmente se necesitan.

\subsection{Herramientas y tecnologías}
% Responsable: Diego Eduardo Zapana Choquehuayta
El ecosistema tecnológico utilizado por Amazon para este caso de uso está
construido en su totalidad sobre la nube de AWS, lo cual facilita el escalado
sin necesidad de administrar infraestructura de forma manual. Entre los
servicios principales se encuentran: Amazon S3 y Lake Formation para el
almacenamiento centralizado de datos; Amazon Athena para consultas SQL
\textit{serverless}; AWS Glue para los procesos ETL basados en PySpark; Amazon
SageMaker para el entrenamiento e inferencia de los modelos de \textit{machine
learning}; Amazon DynamoDB como base de datos final que sirve las
recomendaciones; y Amazon MemoryDB (compatible con Redis) para las búsquedas
de baja latencia. La orquestación de todo el flujo de trabajo se realiza
mediante Amazon MWAA (Airflow gestionado), lo que permite definir y monitorear
los distintos \textit{DAGs} (flujos de tareas) del \textit{pipeline}.

\subsection{Métricas de rendimiento y escalabilidad}
% Responsable: Diego Eduardo Zapana Choquehuayta
DynamoDB ofrece un rendimiento uniforme, con tiempos de respuesta de
milisegundos de un solo dígito, independientemente de la escala del sistema.
Durante eventos de tráfico extremadamente alto, como el Prime Day, la base de
datos ha llegado a atender picos de cientos de miles de solicitudes por
segundo sobre tablas que superan los 200\,TB de información. Por su parte,
MemoryDB logra tiempos de lectura del orden de microsegundos y tiempos de
escritura de pocos milisegundos, con un nivel de disponibilidad cercano al
99{,}999\,\%.

En cuanto al volumen de datos, el \textit{data lake} de Amazon almacena
aproximadamente 25\,petabytes de información en S3, sobre los cuales se
entrenan y reentrenan periódicamente los modelos de recomendación. Tanto AWS
Glue como Amazon SageMaker cuentan con mecanismos de autoescalado que permiten
adaptar automáticamente los recursos de cómputo según el volumen de datos y la
demanda de cada mercado o región, optimizando además los costos al utilizar
esquemas de pago por uso (por ejemplo, DynamoDB en modo \textit{on-demand} y
trabajos de Glue con autoescalado, sin necesidad de mantener infraestructura
provisionada de forma permanente).

\subsection{Seguridad y cumplimiento}
% Responsable: Sebastian German Gomez Portugala
Amazon implementa una arquitectura de seguridad por capas para salvaguardar sus almacenes de datos distribuidos y la infraestructura de personalización:
\begin{itemize}
    \item \textbf{Cifrado de datos en tránsito y en reposo:} Utilización del estándar AES-256 administrado mediante AWS KMS (Key Management Service) para datos almacenados en clústeres como DynamoDB y Redshift, combinado con cifrado estricto TLS 1.3 en todas las comunicaciones inter-nodo y API endpoints.
    \item \textbf{Control de acceso granular y principio de menor privilegio:} Aplicación estricta de políticas AWS IAM con asignación de roles dinámicos, aislando los datos de comportamiento de los usuarios de otros sistemas sensibles de pago o logística.
    \item \textbf{Cumplimiento normativo y privacidad:} Adherencia a regulaciones globales como GDPR y CCPA mediante pipelines automatizados de seudonimización y anonimización de datos de navegación y compras antes de alimentar los modelos de filtrado colaborativo.
\end{itemize}

\subsection{Impacto en el negocio}
% Responsable: Sebastian German Gomez Portugala
El motor de recomendaciones impulsado por bases de datos distribuidas constituye el pilar comercial de Amazon:
\begin{itemize}
    \item \textbf{Generación de ingresos directos:} Se calcula que aproximadamente el 35\% de las ventas totales del comercio electrónico de Amazon proviene de las recomendaciones personalizadas en tiempo real ("Los clientes que compraron esto también compraron...").
    \item \textbf{Aumento de la tasa de conversión:} Incremento del valor promedio del carrito mediante sugerencias contextuales de ultra baja latencia durante el proceso de compra (\textit{cross-selling} y \textit{up-selling}).
    \item \textbf{Continuidad operativa masiva:} Alta disponibilidad del 99.999\% (\textit{five nines}) asegurada durante picos extremos de tráfico como Prime Day y Black Friday, manteniendo tiempos de respuesta inferiores a 10 milisegundos.
\end{itemize}

\subsection{Retos y lecciones aprendidas}
% Responsable: Sebastian German Gomez Portugala
El diseño y mantenimiento del sistema de recomendación distribuido presentó diversos desafíos arquitectónicos:
\begin{itemize}
    \item \textbf{Gestión de consistencia (Teorema CAP):} Priorización de la disponibilidad y tolerancia a particiones (sistemas AP) mediante consistencia eventual para evitar cuellos de botella en la experiencia de navegación del cliente.
    \item \textbf{Mitigación de la clave caliente (\textit{Hot Keys}):} Superación de la saturación de particiones causada por productos altamente populares durante ofertas relámpago, resuelta mediante fragmentación dinámica y capas de almacenamiento en caché en memoria como Amazon ElastiCache.
    \item \textbf{Sincronización multirregión:} Desafío de replicar las preferencias e historial del usuario globalmente en tiempo real manteniendo costos operacionales controlados y evitando la duplicación inconsistente de eventos.
\end{itemize}

\section{Caso 2: Netflix --- Big Data y análisis de patrones de consumo}

\subsection{Arquitectura de datos}
% Responsable: Sebastian German Gomez Portugala
La infraestructura de datos de Netflix responde a una arquitectura híbrida y distribuida optimizada para la analítica a escala de petabytes:
\begin{itemize}
    \item \textbf{Data Lake en la nube (Amazon S3 + Apache Iceberg):} Utilización de S3 como almacenamiento primario no estructurado acoplado a Apache Iceberg, lo que permite realizar transacciones ACID y consultas SQL de alto rendimiento sobre petabytes de logs de reproducciones.
    \item \textbf{Persistencia NoSQL de baja latencia (Apache Cassandra):} Empleo de clústeres masivos de Cassandra para el almacenamiento distribuido del estado del usuario, marcadores de reproducción (\textit{bookmarks}) e historiales de visualización de millones de suscriptores concurrentes.
    \item \textbf{Capa de almacenamiento en memoria (EVCache):} Integración de una capa distribuida basada en Memcached para servir datos de perfiles y personalización con latencias de un solo dígito de milisegundo a la interfaz del usuario.
\end{itemize}

\subsection{Flujos de datos y pipelines}
% Responsable: Sebastian German Gomez Portugala
El ecosistema de procesamiento de Netflix gestiona billones de eventos diarios divididos en dos vías principales:
\begin{itemize}
    \item \textbf{Ingesta distribuida (Keystone Pipeline):} Plataforma capaz de capturar e ingerir más de 500 mil millones de eventos diarios (clics, pausas, calidad de video) utilizando Apache Kafka como bus central de mensajería altamente escalable.
    \item \textbf{Procesamiento en tiempo real (Stream Processing):} Motores basados en Apache Flink y Spark Streaming que analizan la telemetría del usuario al instante para ajustar dinámicamente el bitrate de streaming y alimentar sistemas de recomendación reactivos.
    \item \textbf{Procesamiento por lotes (Batch Analytics):} Procesos ejecutados sobre Apache Spark y Trino para entrenar periódicamente algoritmos de aprendizaje automático que determinan las carátulas personalizadas (\textit{artwork personalization}) y la disposición del catálogo en pantalla.
\end{itemize}
